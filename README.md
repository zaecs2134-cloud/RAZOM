# РАЗОМ 2.0 — світлий інтерфейс + заявки без реєстрації

**Навчальна демонстраційна версія МАН. Не використовуйте справжні контакти, адреси чи медичні дані та не покладайтеся на неї у кризовій ситуації.** Додано інтеграцію Google Gemini API; без ключа працює локальний резервний аналіз.

## Що змінилося

- Мінімалістична адаптивна головна сторінка: **«Мені потрібна допомога» / «Я хочу допомогти»**.
- Людина подає заявку **без акаунта** за три кроки; обов'язкових вуличної адреси, пароля й електронної пошти немає.
- Після створення надається номер заявки і **секретний код**, яким можна перевіряти лише її статус. Код не повертається повторно, у базі зберігається його SHA-256 відбиток.
- Заявка без акаунта спершу потрапляє тільки адміністратору. Після **ручної** перевірки адмін відкриває її волонтерам.
- Реєстрація волонтерів, підтвердження адміном, черга, ресурси, розподіл, статистика та старий API залишилися.
- Для сумісності зі старою базою нові анонімні заявки прив'язуються до технічного акаунта, а секретні коди зберігаються в **новій окремій таблиці `guest_receipts`**. Існуючі таблиці не перебудовуються.
- Обмеження кількості гостьових запитів у пам'яті процесу та приховане поле-антибот **лише для демонстрації**.

## Повернення до версії 1.0

Оскільки оновлення зберігається в **окремій папці**, просто зупиніть сервер 2.0 і відкрийте стару папку. Якщо ви скопіювали стару базу в нову папку, обидві копії є незалежними.

## Запуск на Windows (кроки для старої бази)

1. У **старому** VS Code зупиніть сервер (`Ctrl+C`). Закрийте програму, яка може використовувати стару базу.
2. **Скопіюйте всю стару папку `volunteer_platform`** у надійне місце — це резервна копія.
3. Розпакуйте цей ZIP в **окрему** папку `RAZOM_2_0`. Не перезаписуйте старі файли.
4. Якщо хочете зберегти старі облікові записи та заявки, скопіюйте зі старої папки в корінь `RAZOM_2_0` файли `.env` і `volunteer.db`. Якщо у `.env` зазначено інший `DATABASE_URL`, перевірте, де розташована база; за потреби адаптуйте шлях. **Не надсилайте `.env` нікому.**
5. Відкрийте папку `RAZOM_2_0` у VS Code (`File → Open Folder`). Відкрийте термінал `Terminal → New Terminal`.
6. Виконайте команди по черзі:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Якщо **не** переносили `.env`, створіть нові налаштування:

```powershell
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
```

Відкрийте `.env`, вставте надрукований секрет після `JWT_SECRET=` та збережіть. Якщо створили **нову** базу, лише тоді створіть адміністратора:

```powershell
.\.venv\Scripts\python.exe create_admin.py
```

Запустіть сайт:

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

Відкрийте `http://127.0.0.1:8000`.

> ВАЖЛИВО: якщо ви скопіювали стару базу й `.env`, старий адміністратор **уже існує**. Повторно запускати `create_admin.py` не потрібно. Якщо файл `.env` не скопійовано, не запускайте стару базу з новими налаштуваннями навмання: спочатку перевірте `DATABASE_URL`.

## Сценарій тестування

1. На головній натисніть **«Створити заявку»**, заповніть форму лише **вигаданими** даними, наприклад `+380000000000`.
2. Збережіть номер і секретний код, перейдіть в **«Перевірити заявку»** — має з'явитися «Очікує перевірки».
3. Виберіть **«Вхід»**, увійдіть під старим адміністратором або створеним у попередньому кроці.
4. Перейдіть у вкладку **«Адміністрування» → «Нові заявки без реєстрації»**; перегляньте тестові контакти та натисніть **«Перевірено — відкрити волонтерам»**.
5. Зареєструйте волонтера в окремому браузері або вийшовши. Поверніться до адміністратора і підтвердьте його обліковий запис.
6. Під волонтером знайдіть заявку, візьміть у роботу; додайте тестовий ресурс і виділіть потрібну кількість. Позначте заявку виконаною.
7. У формі статусу з початковими номером і секретним кодом побачите оновлений стан.

## Тести

```powershell
.\.venv\Scripts\python.exe -m pip install pytest httpx
.\.venv\Scripts\python.exe -m pytest -q
```

`http://127.0.0.1:8000/docs` — опис усіх API.  Під час тестів використовується окрема база в пам'яті: ваша `volunteer.db` не зачіпається.

## Для реального публічного запуску ще НЕ ГОТОВО

- Телефон **не підтверджується** SMS/Telegram; користувач може вказати вигаданий чи чужий номер.
- Rate-limit працює **лише в пам'яті** одного Python-процесу і скидається під час перезапуску. Потрібні спільний лімітатор, антибот і контроль зловживань.
- Секретний код — це лише механізм **перегляду статусу**, не верифікація особи та не дозвіл на редагування заявки.
- Для безпечної обробки справжніх персональних/медичних даних потрібні перевірки безпеки, керування згодою/видаленням даних, захист доступу, резервні копії, належні правила обробки й організаційна команда.
- Gemini API підключається через `GEMINI_API_KEY` у `.env`. Передається опис заявки з маскуванням типових контактних даних, категорія та узагальнені параметри. Локальні правила залишаються резервним режимом; Gemini не може знизити визначений ними пріоритет. Тестуйте лише на вигаданих даних і не дозволяйте моделі самостійно ухвалювати рішення про лікування чи евакуацію. Деталі — у `START_HERE_UA.md`.
- Історичний API акаунтів заявників збережено для сумісності; новий інтерфейс робить акцент на простішому шляху **без акаунта**.

План інтеграції ШІ: `AI_NEXT.md`.

## Нове: аналіз заявок, дві черги та Telegram-бот

**Аналіз (`ai_service.py`).** За наявності Gemini API кожна заявка отримує рівень: 🔴 критична, 🟠 висока, 🟡 звичайна, 🟢 може зачекати, разом із поясненням «чому». За наявності `GEMINI_API_KEY` аналізує справжня мовна модель Google Gemini; якщо ключа немає або API недоступний, автоматично використовуються прозорі локальні правила. Аналіз лише підіймає пріоритет відносно вказаного заявником, ніколи не знижує його. Рішення завжди за людиною.

**Дві черги (`GET /queues`)** для волонтерів та адмінів: «За потребою» (спершу критичні) і «За часом» (кнопка перемикає «спочатку нові» / «спочатку старі»). Нижче показуються заявки «У роботі».

**Telegram-бот (`telegram_bot.py`).**
1. У @BotFather створіть бота, токен вставте в `.env` як `TELEGRAM_BOT_TOKEN`, ім'я бота як `TELEGRAM_BOT_USERNAME`.
2. Перезапустіть сервер. Бот працює через long polling, публічна адреса не потрібна.
3. У кабінеті волонтера чи адміна натисніть «Підключити Telegram» і відкрийте бота. Код одноразовий і діє 15 хв.
4. Бот надсилає лише категорію, місто, рівень критичності та посилання. Телефон, адреса й опис у Telegram не передаються. Посилання `/#request-№` відкриває заявку на сайті після входу.
5. Команди: `/queue` (за потребою), `/new` (найновіші), `/unlink`.

Нових пакетів не потрібно. Нова таблиця `telegram_link_codes` створюється автоматично, наявні таблиці не змінюються.

Небезпечний `POST /me/telegram` (довільний chat_id) видалено: чат тепер підтверджує сам Telegram.
